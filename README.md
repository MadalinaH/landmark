# Where Is This? - Cross-Modal Landmark Recognition System

A system that identifies landmarks from photos, retrieves them from natural-language
descriptions, generates AI-authored travel narratives, and audits its own geographic
bias - all explained through attention visualisation and confidence calibration.

---

## What It Does

| Tab | Input | Output |
|-----|-------|--------|
| **Image search** | A photo of a landmark | Top-K matches with descriptions, coordinates, confidence scores, and sensitive-site warnings |
| **Text search** | A natural-language description | Matching landmarks ranked by semantic similarity, with optional BM25 keyword boosting and attention visualisation |
| **Instagram post** | 2–5 landmark photos | A travel Instagram post generated by Claude, grounded in retrieved Wikipedia descriptions |
| **Model report** | - | Live performance metrics, geographic bias chart, confidence calibration curve, and responsible AI summary |

---

## How It Works

### Core concept: shared embedding space

CLIP (Contrastive Language–Image Pretraining) maps both images and text into the same
512-dimensional vector space:
- A photo of the Eiffel Tower and *"iron lattice tower on the Champ de Mars in Paris"*
  map to nearby vectors - without any explicit landmark training.
- Similarity is measured by cosine similarity (inner product of L2-normalised vectors).

### Retrieval pipeline

```
Query image / text
    │
    ▼ CLIP ViT-B-16 encoder (fine-tuned)
512-d L2-normalised vector
    │
    ▼ FAISS IndexFlatIP (exhaustive inner product search)
Top-K nearest landmark vectors
    │
    ├─ image query  → image index (pre-averaged image embeddings)
    └─ text query   → text index  (pre-computed description embeddings)
```

**Why two indexes?** Image-to-image retrieval scores 0.85–0.94 for correct matches;
cross-modal text-to-image scores 0.28–0.35. Using the image index for photo queries
and the text index for text queries keeps each modality in its optimal range.

### BM25 hybrid retrieval

CLIP can score semantically similar landmarks almost identically ("Colosseum" vs
"Pantheon" - both ancient Roman structures). BM25 adds a keyword signal for
content words:

```
combined = 0.7 × clip_score + 0.3 × bm25_normalised
```

Queries are stopword-filtered before BM25 scoring. If the filtered query produces
near-zero BM25 scores (no keyword signal), the system falls back to CLIP-only.

### CLIP fine-tuning

The base model was pretrained on 400M general image-text pairs. Fine-tuning adapts
the final layers to the landmark domain using 1,184 image-text pairs.

**Strategy:** 86% of parameters are frozen. Only the last two transformer blocks of
both encoders and the projection heads are fine-tuned (~14% of parameters). This
preserves general representations while reducing overfitting on the small dataset.

**Result:** Hits@1 improves from 95% → 97%, MRR from 0.973 → 0.983. The 95%
bootstrap CI lower bound rises from 0.91 → 0.95, indicating more consistent
performance across landmarks. See `evaluation/FINDINGS.md` for full analysis.

### Ablation study

Four conditions evaluated via leave-one-out on all 148 indexed landmarks:

| Condition | Hits@1 | Hits@3 | MRR | 95% CI |
|-----------|--------|--------|-----|--------|
| Baseline CLIP | 141/148 (95%) | 147/148 (99%) | 0.973 | [0.91, 0.99] |
| Fine-tuned CLIP | 144/148 (97%) | 147/148 (99%) | 0.983 | [0.95, 0.99] |

Text retrieval (149 landmark name queries): both models achieve 99% Hits@1,
confirming CLIP generalises well to landmark text queries without text-encoder
fine-tuning.

### Confidence calibration

Thresholds calibrated empirically:
- **Image search**: `0.82` - correct matches cluster at 0.85–0.94
- **Text search**: `0.25` - correct matches cluster at 0.28–0.35

Results below the threshold show a ⚠️ Low confidence warning. The calibration
chart (score distributions for correct vs incorrect matches) is in the Model
Report tab and at `evaluation/calibration_chart.png`.

### Geographic bias audit

Leave-one-out evaluation across all 148 landmarks, grouped by region. Results
shown as a colour-coded bar chart (red <70%, amber <85%, green ≥85%) in the
Model Report tab and at `evaluation/bias_chart.png`.

The dataset skews towards Europe + Vienna (39%). Underrepresented regions
(Oceania 7%, Natural 3%) show lower Hits@1. See `evaluation/FINDINGS.md`
for failure analysis and `data/DATASET_CARD.md` for dataset documentation.

### EXIF GPS extraction

Uploaded photos are checked for embedded GPS coordinates. If found:
- A privacy warning is displayed before any processing
- A dual-pin map shows the photo's GPS location alongside the matched landmark

Most smartphone photos embed precise coordinates that users rarely notice.

### Attention visualisation

The text search tab includes a "Why these results?" expander powered by BertViz.
Per-head attention patterns across all 12 layers of CLIP's text encoder show which
tokens drive retrieval. Content words (landmark names, architectural adjectives)
attract disproportionate attention in later layers.

### Sensitive site flagging

15 landmarks are flagged with `sensitive: true` and a `sensitivity_reason` in
`landmarks.json`. Categories: active religious sites with access restrictions,
sites with photography prohibitions, solemn memorials, sacred indigenous sites.
A yellow warning box is shown in the UI whenever a flagged landmark is retrieved.

### Instagram post generation

The Instagram tab accepts 2–5 photos, identifies each landmark, then calls Claude
Haiku with a structured prompt listing retrieved Wikipedia descriptions. The post
includes a hook line, 2–4 paragraphs mixing personal narrative with verified facts,
and 10–15 hashtags. Claude is instructed to ground all factual claims in the provided
descriptions. A disclaimer is shown beneath every generated post.

### Image generation

The text search tab optionally generates a Stable Diffusion image from the query,
displayed alongside the retrieval results. Supports SDXL (best quality, GPU) and
SD 2.1 (lighter fallback). Useful for comparing what the model *imagines* versus
what the retrieval index actually contains.

## Responsible AI

| Feature | Implementation |
|---------|---------------|
| **Confidence warnings** | Scores below empirical thresholds surface a ⚠️ warning instead of presenting results as certain |
| **EXIF privacy** | Uploaded photos are checked for embedded GPS; users are warned before their location is shared |
| **Geographic bias** | Leave-one-out audit quantifies Hits@1 per region; chart shown in Model Report tab |
| **Sensitive sites** | 15 landmarks flagged with access/photography restrictions; shown as yellow warnings in results |
| **Grounded generation** | Instagram posts grounded in Wikipedia descriptions; Claude instructed not to invent facts |
| **Disclaimer** | Every generated post carries a fact-checking disclaimer |
| **Dataset card** | `data/DATASET_CARD.md` documents composition, biases, and licence |
| **Model card** | `MODEL_CARD.md` documents training, evaluation, limitations, and intended use |

## Libraries

| Library | Role |
|---------|------|
| **open_clip** | CLIP ViT-B-16 (OpenAI weights + fine-tuned checkpoint). Encodes images and text into 512-d vectors. |
| **FAISS** (`faiss-cpu`) | IndexFlatIP for exact cosine similarity search. Two indexes: image embeddings and text embeddings. |
| **rank_bm25** | BM25Okapi over landmark descriptions. Combined with CLIP scores in HybridSearcher. |
| **transformers** | HuggingFace `CLIPTextModel` - used only for attention extraction (open_clip doesn't expose per-layer tensors). |
| **BertViz** | Renders interactive per-head attention HTML injected into Streamlit. |
| **anthropic** | Official Anthropic SDK. Claude Haiku generates Instagram posts from retrieved descriptions. |
| **diffusers** | StableDiffusionXLPipeline and StableDiffusionPipeline for text-to-image generation in the text search tab. |
| **accelerate** | Mixed-precision and device management for diffusion pipelines. |
| **Pillow** | Image loading, CLIP preprocessing, and EXIF GPS extraction. |
| **Streamlit** | Web UI. `@st.cache_resource` loads models once per server process. Four tabs. |
| **pandas** | DataFrame wrapper for `st.map` coordinate pins. |
| **matplotlib** | Geographic bias bar chart and confidence calibration histogram. |
| **requests** | Wikipedia REST API and Wikidata SPARQL in `scripts/fetch_descriptions.py`. |
| **python-dotenv** | Loads `.env` so secrets never appear in source code. |
| **tqdm** | Progress bars in index-building and evaluation scripts. |

## Setup

```bash
# 1. Install dependencies
uv sync

# 2. Add secrets to .env
echo "ANTHROPIC_API_KEY=sk-ant-..." >> .env        # needed for Instagram post tab
echo "CLIP_WEIGHTS_PATH=/path/to/clip_finetuned_best.pt" >> .env  # optional: fine-tuned weights

# 3. Build the indexes (run once after images are in data/images/)
uv run python scripts/fetch_descriptions.py   # enrich landmarks.json
uv run python scripts/build_text_index.py     # text index
uv run python scripts/build_index.py          # image index

# 4. Run the app
uv run streamlit run app/streamlit_app.py
```

---

## Fine-tuning CLIP

```bash
# 1. Create a virtual environment (required on managed servers)
python3 -m venv .venv && source .venv/bin/activate
pip install torch torchvision open-clip-torch numpy tqdm pillow python-dotenv

# 2. Train (tested on NVIDIA L40S, ~5 minutes)
python3 scripts/train_finetune.py --epochs 20 --batch-size 128 --device cuda

# 3. Point the pipeline at the best checkpoint
echo "CLIP_WEIGHTS_PATH=/path/to/data/checkpoints/clip_finetuned_best.pt" >> .env

# 4. Rebuild indexes with fine-tuned model
python3 scripts/build_text_index.py
python3 scripts/build_index.py
```

| Flag | Default | Description |
|------|---------|-------------|
| `--epochs` | 20 | Training epochs |
| `--batch-size` | 128 | Images per batch |
| `--lr` | 5e-6 | AdamW learning rate |
| `--unfreeze-blocks` | 2 | Last N transformer blocks to fine-tune |
| `--device` | cuda | `cuda` or `cpu` |

```bash

source .venv/bin/activate
uv run streamlit run app/streamlit_app.py

# On your local machine (separate terminal)
ssh -L 8501:localhost:8501 <user>@<server>
# Then open http://localhost:8501
```
