# Where Is This? - Cross-Modal Landmark Recognition System

An project that identifies landmarks from photos, retrieves them from natural-language descriptions, and generates AI-authored travel narratives - all explained through attention visualisation and confidence calibration.

---

## What It Does

The system solves three related tasks through a single shared embedding space:

| Task | Input | Output |
|------|-------|--------|
| **Image search** | A photo of a landmark | Top-K matching landmarks with descriptions, coordinates, and confidence scores |
| **Text search** | A natural-language description | Matching landmarks ranked by semantic similarity, with optional BM25 keyword boosting |
| **Instagram post** | 2–5 landmark photos | A travel Instagram post generated by Claude, grounded in retrieved Wikipedia descriptions |

---

## How It Works

### Core concept: shared embedding space

CLIP (Contrastive Language–Image Pretraining) maps both images and text into the same 512-dimensional vector space. This means:
- A photo of the Eiffel Tower and the sentence *"iron lattice tower on the Champ de Mars in Paris"* map to nearby vectors - without any explicit training on landmarks.
- Similarity is measured by cosine similarity (inner product of L2-normalised vectors).

### Retrieval pipeline

```
Query image
    │
    ▼ CLIP ViT-B-16 image encoder
512-d L2-normalised vector
    │
    ▼ FAISS IndexFlatIP (exhaustive inner product search)
Top-K nearest landmark vectors
    │
    ├─ mode="image"  → compared against pre-averaged image embeddings
    └─ mode="text"   → compared against pre-computed description embeddings (cross-modal)
```

**Why two indexes?**
Image-to-image retrieval is more accurate for photo queries (cosine scores 0.85-0.94 for correct matches vs. 0.28-0.35 cross-modal). The text index is used for the text search tab where the query is already text.

### BM25 hybrid retrieval

CLIP sometimes scores semantically similar but wrong landmarks almost identically (Colosseum vs. Pantheon are both "ancient Roman structures"). When the query contains landmark-specific keywords (proper nouns, architectural terms), BM25 adds a keyword signal:

```
combined = 0.7 × clip_score + 0.3 × bm25_normalised
```

BM25 queries are stopword-filtered before scoring to prevent common words ("place", "where") from spuriously matching unrelated descriptions. If no keyword signal exists (near-zero BM25 max score), the system falls back to CLIP-only.

### Confidence calibration

Thresholds are calibrated on a 5-image golden set:
- **Image search**: `0.82` - correct matches score 0.85–0.94
- **Text search**: `0.25` - correct matches score 0.28–0.35

Results below the threshold show a "⚠️ Low confidence" warning in the UI.

### EXIF GPS extraction

When an image is uploaded in the Image search tab, its EXIF metadata is parsed for GPS coordinates. If present:
- A privacy warning is displayed ("this photo contains embedded GPS - uploading shares your location")
- A dual-pin map shows both the photo's GPS location and the matched landmark's coordinates side by side

This feeds directly into the responsible-AI audit: most smartphone photos embed precise coordinates that users rarely notice.

### Attention visualisation

The text search tab includes a "Why these results?" expander powered by BertViz. It shows per-head attention patterns across all 12 layers of CLIP's text encoder for the query. Later layers typically show content words (landmark names, architectural adjectives) attracting disproportionate attention - making the retrieval decision partially interpretable.

Implementation note: a separate HuggingFace `CLIPTextModel` instance is used only for attention extraction, because open_clip does not expose per-layer attention tensors. The open_clip model continues to handle all retrieval.

### Instagram post generation

The Instagram post tab accepts 2–5 photos, identifies each landmark using image search, then calls Claude Haiku with a structured prompt listing the retrieved descriptions. The prompt produces a single Instagram post in influencer style: a punchy hook line, 2–4 short paragraphs mixing personal feeling with real facts, and a block of 10–15 hashtags. Claude is instructed to ground every factual claim strictly in the provided descriptions - hallucination is limited to prose style rather than invented facts. Low-confidence identifications are flagged to the user before generation so they can judge whether the retrieved landmark is correct.

## Libraries and How They Collaborate

| Library | Role |
|---------|------|
| **open_clip** | Loads CLIP ViT-B-16 (OpenAI weights). Encodes images and text queries into 512-d vectors at both index-build time and search time. |
| **FAISS** (`faiss-cpu`) | IndexFlatIP stores pre-computed landmark embeddings and performs exact cosine similarity search. Two indexes: `faiss_index.bin` (image embeddings) and `faiss_text_index.bin` (text embeddings). |
| **rank_bm25** | BM25Okapi built over landmark descriptions at HybridSearcher initialisation. Scores are combined with CLIP scores; stopwords are stripped from queries before scoring. |
| **transformers** | HuggingFace `CLIPTextModel` and `CLIPTokenizerFast` - used *only* by the attention module to extract per-layer attention tensors. Not used for retrieval. |
| **BertViz** | Renders interactive head_view HTML from the attention tensors. Output is injected into Streamlit via `st.components.v1.html`. |
| **anthropic** | Official Anthropic Python SDK. Called by the Instagram post module to generate posts from retrieved landmark descriptions. Claude Haiku is used by default for speed and cost. API key loaded from `.env`. |
| **Pillow** | Image loading and preprocessing (CLIP transform), and EXIF GPS tag extraction (`_getexif` + `GPSTAGS`). |
| **Streamlit** | Web UI. `@st.cache_resource` ensures CLIP model and FAISS index are loaded once per server process. Three tabs: Image search, Text search, Instagram post. |
| **pandas** | DataFrame wrapper for `st.map` coordinate pins. |
| **requests** | Wikipedia REST API and Wikidata SPARQL calls in `scripts/fetch_descriptions.py`. |
| **tqdm** | Progress bars in index-building and description-fetching scripts. |
| **python-dotenv** | Loads `.env` at import time in `config.py` so secrets never appear in source code. |

## Project Structure

```
├── app/
│   └── streamlit_app.py       # Streamlit UI - three tabs, sidebar settings
├── config.py                  # All constants and secrets (loaded from .env)
├── data/
│   ├── landmarks.json         # 149 landmarks with descriptions and coordinates
│   ├── images/                # One folder per landmark, ~8 images each
│   ├── eval/                  # 5 golden test images for evaluate.py
│   ├── faiss_index.bin        # Image-embedding FAISS index
│   ├── faiss_text_index.bin   # Text-embedding FAISS index
│   ├── embeddings.npy         # Raw image embeddings (N×512)
│   ├── text_embeddings.npy    # Raw text embeddings (N×512)
│   └── metadata.json          # Metadata for image index (subset of landmarks.json)
├── scripts/
│   ├── build_index.py         # Embed images → faiss_index.bin
│   ├── build_text_index.py    # Embed descriptions → faiss_text_index.bin
│   ├── fetch_descriptions.py  # Enrich landmarks.json with Wikipedia + Wikidata
│   ├── fetch_eval_images.py   # Download golden-set test images
│   └── evaluate.py            # Hits@1, Hits@3, MRR on 5-image golden set
└── src/
    ├── embeddings/
    │   ├── image_encoder.py   # CLIP image embedding + averaging
    │   └── text_encoder.py    # CLIP text embedding + chunking for long descriptions
    ├── retrieval/
    │   ├── index.py           # FAISS index build / save / load
    │   ├── search.py          # LandmarkSearcher (image query → index)
    │   ├── text_search.py     # TextSearcher (text query → text index)
    │   └── hybrid_search.py   # HybridSearcher (CLIP + BM25 fusion)
    ├── explainability/
    │   └── attention.py       # BertViz attention HTML for text queries
    ├── generation/
    │   └── travel_story.py    # Claude API Instagram post generation
    └── utils.py               # EXIF GPS extraction + folder name sanitisation
```

## Setup

```bash
# 1. Install dependencies
uv sync

# 2. Add your Anthropic API key (only needed for travel story tab)
echo "ANTHROPIC_API_KEY=sk-ant-..." >> .env

# 3. Build the indexes (run once after images are in data/images/)
uv run python scripts/fetch_descriptions.py   # enrich landmarks.json
uv run python scripts/build_text_index.py     # primary text index
uv run python scripts/build_index.py          # image index

# 4. Run the app
uv run streamlit run app/streamlit_app.py
```

## Evaluation

```bash
# Download 5 golden test images
uv run python scripts/fetch_eval_images.py

# Run evaluation (reports Hits@1, Hits@3, MRR)
uv run python scripts/evaluate.py
```

## Responsible AI Notes

- **Confidence calibration**: scores below empirically determined thresholds surface a warning rather than presenting results as certain.
- **EXIF privacy**: the app detects and warns about GPS metadata in uploaded photos before the user can unknowingly share their location.
- **Grounded generation**: Instagram posts are generated from retrieved Wikipedia descriptions; Claude is instructed not to invent facts, and a disclaimer is shown beneath every post.
- **Geographic bias**: the 149-landmark dataset skews towards European landmarks. A bias audit (Hits@1 per continent) is planned for Phase 4.
